# gotchas — traps that have bitten, with the fix

- **Stray shadow files in repo root** (`12`, `20%`, `10.2f}`, `Alpaca`, …): the ruflo `pre-bash`/`post-bash` hooks re-parsed each Bash command's TEXT through a shell, so a `>token` inside it (Python format specs like `{cash:>10.2f}`, or `>1000%`) became a redirect creating an empty file in the cwd. Proven by isolation (token in command text → file; token only in file content → none). FIXED 2026-07-08: removed the `matcher:"Bash"` hooks from project + user `settings.json`, deleted `.mcp.json` (ruflo MCP) and the `claudeFlow` config block, disabled the RuFlo statusline. Takes effect next session (hooks load at startup). (record AW + 2026-07-08 session)
- **cmd.exe batch parse corruption**: a single non-ASCII byte (e.g. an em-dash in a REM) OR a stray root file shadowing a builtin name (a 0-byte `ECHO`) silently corrupts the ENTIRE `.bat` parse → garbled `'X' is not recognized`. Keep `rebalance.bat`/`daily.bat` pure ASCII; check these two things first when a scheduled run aborts fast. (CLAUDE.md, record AS)
- **Inline `python -c "..."` / `node -e` with backslashes breaks** under the Bash tool (escaping mangles `\\`, `>`) — write a temp `.py`/`.js` in the scratchpad and run it instead. (global CLAUDE.md; hit again this session with graphify)
- **Never rewrite JSON data files with PowerShell** — corrupts emoji/UTF-8. Use Node or Python. (global CLAUDE.md)
- **yfinance split misapplication tell**: a >1000% single-day move in the movers panel = a split applied to history days early (KLAC 10:1, 2026-06-12) → needs manual position/NAV repair. (CLAUDE.md, memory `corporate_action_splits`)
- **yfinance incomplete publication + late settling**: a trading day's closes arrive for only ~4,400 of ~5,200 tickers at ~5:15pm and fill in over the following hours/day. `daily_price_refresh` fetches a ~30-day RANGE, so prior days SELF-HEAL on later runs — e.g. 2026-07-08 was 4,379 at ~13:20 and settled to 5,207 by evening. The same-day 17:15 MTM is what catches the universe mid-publication. NOW AUTO-DETECTED + BLOCKED by `check_coverage.py` (M2.1, wired into daily.bat M2.2, floor 5,000). **First live catch 2026-07-09 17:17** (4,381<5,000 → MTM skipped, no 07-09 nav row). **RESOLVED by M3.5 self-healing catch-up (record BN):** `daily.bat` now runs `mtm_catchup.py`, which marks every SETTLED missing day (today included) each run and leaves pending days for next time — so a late day like 07-09 heals automatically once it settles, and the daily task exits 0 on a normal pending day. Never MTM below the floor to "close" a gap; catch-up gates each day on `coverage_status()`. To heal a specific day by hand: refresh, then `mtm_catchup` once `check_coverage --date <D>` passes. (record BH/BI/BN)
- **Sub-penny nanocaps look like split anomalies**: a KLAC-style ">1000% single-day move" detector fires on nanocaps flickering $0.0007→$0.01 (huge ratio, trivial absolute). `check_anomalies.py` applies a `--min-price` floor (default $1) to the cache-wide rule to skip them; held names are exempt (universe filters keep sub-penny names out of holdings). (record BD)
- **`monthy-llm-rebalance` — the typo is real.** Renaming the scheduled task breaks the automation chain. Leave it. (CLAUDE.md)
- **graphify**: `docs/` is intentionally excluded (`.graphifyignore`); the incremental `--update` path mis-accounts on this repo (`build_merge` drops un-re-extracted nodes → shrinks the graph) — do a full rebuild instead. Old graphs accumulate ghost-duplicate nodes across incremental runs. (2026-07-08 session)
- **`if errorlevel N` is GREATER-OR-EQUAL, so it is blind to a NEGATIVE crash code** (a killed `python.exe` returns `-1073741819` = 0xC0000005, which is not `>= 1`). Capture explicitly instead: `set STEP_RC=%errorlevel%` then `if not "%STEP_RC%"=="0" ...`. Cost twice: `rebalance.bat`'s 15 gates let a crashed `alpaca_sync --execute` stamp OK and exit 0 (record DI.1, fixed 2026-08-19), and `daily.bat`'s verify gate let a crashed `verify_run` stamp `verify=PASS` and exit 0 (record DL.1, fixed 2026-08-21). Both files now use explicit capture; `monthly_auto.bat` (dormant) and `start_all.bat` still use the old form. (records DI, DL)
- **A parenthesized cmd.exe block ends at the FIRST unescaped `)` — including one inside echo TEXT.** `if not errorlevel 1 ( echo === audit (day 1 of month) === & <cmd> )` closed early, so the command fell OUTSIDE the block and ran EVERY day for three days undetected. `daily.bat`'s header mandates `goto` over blocks for this reason. Escape as `^(`/`^)` or use `goto`. (record DG.1)
- **Claude Code `Bash(...)` deny rules are PREFIX matchers.** `Bash(:*token:*)` cannot block a token mid-command — the leading `:*` is a literal colon, so the rule requires the command to START with it and can never fire. Four deny rules written that way were recorded as a security fix and covered nothing. Enforcement that must see the WHOLE command string belongs in a PreToolUse hook. (records DJ.1 wrong, DK.1 correct; memory `bash-deny-rules-are-prefix-matchers`)
- **The trading guard is escaped by any `.bat` wrapper** — OPEN as of 2026-09-06. `scripts/hooks/pretooluse-trading-guard.js` reads only `payload.tool_input.command` and cannot see subprocesses, so `cmd /c ...\rebalance.bat` matches none of its 5 rules while that batch runs four guarded operations (`:92`,`:107`,`:138`,`:162`,`:168` rule 2; `:200` `alpaca_sync --all --execute`, rule 4). PROVEN empirically 2026-09-01 — the batch ran end to end, 128 real Alpaca paper orders included. `monthly_auto.bat` reaches the same four by calling `rebalance.bat`, so any fix must recurse. A fix must also strip `REM`/`::` comments before matching, else `overlay_prep.bat` (which names a guarded op only in a comment at `:6`) is wrongly denied. (records DN.3, DO.1 finding 2, DP.6)
- **The guard matches the RAW command string, so merely NAMING a guarded operation is denied** — a Bash heredoc writing documentation about `paper_rebalance` is blocked. Deliberate: a false deny costs one rephrase, a false allow costs a real trade. Workaround: author content with the Write tool, keep the Bash command string free of the tokens. (record DK; hit again 2026-09-06)
- **yfinance rate-limits the refresh PER TICKER, inside batches that still return rows** (from ~batch 15 of 30; 2026-09-22 had A-J 94% / K-Z 46% of closes). Neither old refresh guard fired. `daily_price_refresh` now retries recently-traded tickers that returned nothing after 60/120/240 s and exits 1 at >=5% still missing (aborts the monthly rebalance). A None/NaN from Yahoo is NOT a missing bar until it survives those cooldowns - DZ misread one as a vendor hole (corrected in EC). (records DY, DZ, EC)
- **`paper_nav` is SEALED** (stage 5, live since 2026-09-23): a row with a newer row for the same sleeve refuses REPLACE/UPDATE/DELETE unless `paper_nav_restatement` logged that (sleeve, date) in the last 10 min. Repair history only with `remark_nav_day --date D --execute --reason "..."`. A "sealed" IntegrityError from an old one-off reset script is the guard working. `compute_nav` replays the ledger for a past date the sleeve traded after (DW). (records DW, DX)
